## 4. 部署步骤

### 4.1 CI/CD 流程 (GitHub Actions)

```yaml
# .github/workflows/deploy.yml
name: Deploy
on:
  push:
    branches: [main]

jobs:
  deploy:
    runs-on: ubuntu-latest
    environment: production
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: npm

      - run: npm ci

      - name: Generate Prisma Client
        run: npx prisma generate

      - name: Run Tests
        run: |
          npx vitest run --coverage
          npx playwright test

      - name: Build
        run: npm run build
        env:
          DATABASE_URL: ${{ secrets.DATABASE_URL }}
          NEXTAUTH_SECRET: ${{ secrets.NEXTAUTH_SECRET }}

      - name: Deploy to CloudBase
        run: npx tcb deploy --mode production
        env:
          TCB_ENV_ID: ${{ secrets.TCB_ENV_ID }}
          TCB_SECRET_ID: ${{ secrets.TCB_SECRET_ID }}
          TCB_SECRET_KEY: ${{ secrets.TCB_SECRET_KEY }}

      - name: Migrate Database
        run: npx prisma migrate deploy
        env:
          DATABASE_URL: ${{ secrets.DATABASE_URL }}

      - name: Notify Slack
        if: always()
        uses: 8398a7/action-slack@v3
        with:
          status: ${{ job.status }}
          fields: repo,commit,author
```

### 4.2 手动部署步骤

```bash
# 1. 拉取最新代码
git pull origin main

# 2. 安装依赖
npm ci --production=false

# 3. 生成 Prisma 客户端
npx prisma generate

# 4. 执行数据库迁移
npx prisma migrate deploy

# 5. 构建
npm run build

# 6. 重启服务（PM2 或容器）
pm2 restart phoebe-museum --update-env

# 7. 验证
curl -f https://phoebemuseum.art/api/health || exit 1
```

## 5. 数据库迁移

### 5.1 迁移命令

```bash
# 开发环境
npx prisma migrate dev --name <migration_name>

# 生产环境（仅 deploy，不自动创建）
npx prisma migrate deploy

# 回滚（手动操作，需 DBA 介入）
npx prisma migrate resolve --rolled-back <migration_name>
```

### 5.2 迁移策略

- 生产环境**不自动**执行 `migrate dev`
- 每次 PR 合并前，CI 执行 `migrate deploy` 在 staging 验证
- 生产迁移在低峰期（凌晨 2-4 点）执行
- 迁移前必须备份

```ts
Sentry.init({
  dsn: process.env.SENTRY_DSN,
  tracesSampleRate: 0.1,    # 生产环境 10% 采样
  replaysSessionSampleRate: 0.01,
  replaysOnErrorSampleRate: 1.0,

```

### 7.2 健康检查

```ts
// app/api/health/route.ts
export async function GET() {
  try {
    await prisma.$queryRaw`SELECT 1`;
    await redis.ping();
    return Response.json({ status: 'ok', timestamp: Date.now() });
  } catch {
    return Response.json({ status: 'error' }, { status: 503 });
  }
}
```

### 7.3 告警规则

| 指标 | 阈值 | 动作 |
|------|------|------|
| HTTP 5xx 错误率 | > 1% / 5min | Slack 告警 |
| 响应时间 P95 | > 2s | Slack 告警 |
| 数据库连接池 | > 80% | Slack + 邮件 |
| Redis 内存 | > 80% | Slack |
| 磁盘空间 | < 20% | 邮件 + Slack |
| 健康检查失败 | 连续 3 次 | 自动重启 |

## 8. 备份策略

| 数据 | 频率 | 保留 | 方式 |
|------|------|------|------|
| PostgreSQL 全量 | 每日凌晨 3 点 | 30 天 | pg_dump → OSS |
| PostgreSQL WAL | 实时 | 7 天 | 流式备份 |
| Redis RDB | 每日凌晨 3:30 | 7 天 | bgsave → OSS |
| OSS 文件 | 跨区域复制 | 永久 | OSS 跨区域复制 |

## 9. 回滚方案

### 9.1 应用回滚

```bash
# 查看部署历史
pm2 jlist | jq '.[].created_at'

# 回滚到上一版本
pm2 revert phoebe-museum

# 或指定版本
git checkout <previous-commit>
npm run build && pm2 restart phoebe-museum
```

### 9.2 数据库回滚

```bash
# 恢复最近备份
pg_restore -d phoebe_prod /backup/phoebe_prod_20260828.sql

# 恢复后验证
npx prisma migrate status
```

### 9.3 灰度发布

- 先部署到 staging
- 通过全部测试后，生产灰度 10% → 50% → 100%
- 每阶段观察 30 分钟
- 异常率超 0.5% 立即回滚
